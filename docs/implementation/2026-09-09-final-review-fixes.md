## Finding dispositions

1. **Admission failures becoming removals or invisible coverage: fixed.** New revisions persist `admission` separately from extraction coverage: `outcomes` counts every observed source status, `unresolved_admissions` counts error observations, `enumeration_complete` records whether enumeration succeeded, and `scope=revision_source_observations` explicitly identifies the revision-wide scope. Error counts are observed paths, not a guessed number of artifacts in an unreadable subtree. Legacy revisions derive this summary from their existing observation records at read time without rewriting published documents. Search/result continuations retain the summary in mandatory response/state, and bounded negatives copy it alongside coverage and `count_scope=known_selected_representation`. Exact zero remains permissible for that selected representation; it does not assert absence in unresolved source scope. `changes.removed` excludes unresolved paths. An incomplete enumeration conservatively makes all absent old captures unresolved; observed exclusions are separately classified. Old membership is never relabeled freshly captured. A failed entry-type observation also marks enumeration incomplete because it may hide a directory. Public ingestion regressions cover an unreadable PDF, unreadable subtree and unsafe symlink root, both initially and after a successful predecessor, through bounded search and finish. Old revisions remain readable. Revision-bound admission pages expose the recorded source outcomes.

2. **Reuse lacking current extraction identity: fixed.** Before successful-cache lookup, the requested recipe includes `adapter_version=tampu-adapters/v2`, `normalization_version=tampu-elements/v1`, the explicit profile version (`poppler-pages/v1` or `unstructured-fast/v1`), profile/options, and Poppler's current `pdftotext -v` identity or the pinned Unstructured image. The existing pinned image, strategy, offline network and memory options remain. The versions must be maintained when adapter/profile/normalization behavior changes. Legacy records missing these identities remain readable but do not match a new processing attempt. A failed current version probe creates a controlled failed projection rather than returning cached success, retaining its raw diagnostic separately from the controlled loss message. Same-store regressions cover Poppler/adapter/normalization upgrades, unchanged-recipe reuse, failed probing, retained old files and old published evidence, and `processing_changed` on a successor. There is no fallback or historical re-extraction.

3. **Coarse dates treated as exact dates: fixed.** `publication-date-interval/v1` treats a year as January 1 through December 31, a month as its actual first through last calendar day, and a day as one day. Bounds are inclusive; omitted bounds are unbounded. Full containment is a definite match, disjoint intervals are excluded, and partial overlap is unresolved. Missing assertions are also unknown; unsupported legacy precision is treated conservatively as ambiguous. `temporal_scope.ambiguous_intervals` and `missing_values` separately disclose uncertainty, with their sum retained as `unknown_count` and `unknown_or_ambiguous`. Search and negative findings carry this scope even if optional lens configuration is removed by budget fitting. Instant-based temporal fields keep inclusive instant comparisons (`instant-inclusive/v1`). Tests cover year/month/day containment, disjointness and partial overlap, including the January-1 false match and mid-March false exclusion. A real-repository search→finish test verifies the ambiguous interval in an exact selected-subset negative.

4. **Unreachable or unattributed processing detail: fixed.** `describe(collection=..., detail="processing")` returns each selected projection's full recipe/status/coverage record followed by its individual declared-loss records, all carrying artifact and projection IDs. The summary's failure records now carry those identities too. `detail="admission"` uses the same facility for recorded source observations. The first request may resolve current revision; continuation requests repeat returned `revision_id` as `revision` and `continuation` as `detail_cursor`, in the same MCP process. Signed cursors bind collection, revision, detail kind and offset. `detail_limit` accepts 1..100. Complete records advance or return `budget_too_small` plus `minimum_bytes`; when space permits, the error identifies the revision/offset and affected processing record. An individual record larger than the hard 32768-byte ceiling requires owner-local access: an impossible budget increase is not a remedy. No fragment or record is silently skipped. Tests recover seven recipes and all 56 individual losses with default-budget pages after current revision changes, reject a different pinned revision, test the hard budget and oversized-record minimum/identity, and traverse processing/admission pages through actual stdio tools/list and tools/call. Summary detail caps remain five; larger budgets only restore fields omitted for budget, while the detail route reaches later records.
